## Stand it up

1. BAND Desktop on Linux x86_64. Create one agent per file in `mandates/` (Agents, New agent,
   Create your own), choose the file as its role, and set its working directory to the result
   repository. The Claude Code seats use the Claude Code runtime, the Codex seats the Codex
   runtime, and the auditor the OpenCode runtime pointed at Featherless.
2. From the [factory repository](https://github.com/StephenSook/twin-dark-factory), create the
   result repository with `factory/tools/new_run.sh`: one human root commit holding
   `mandates/`, and the commit guard (`factory/tools/pre-commit`) installed before anything else can
   commit. The guard accepts only authors that are committed mandates, keeps seats inside
   `stage-N/`, and refuses nested repositories and caches.
3. Create the BAND room with all six seats. Before the dispatch, start the external observer from
   the factory repository with `python3 factory/tools/room_meter.py start --repo <result> --room <room-id> --checks <checks>`.
   It writes only count metadata under the result repository's `.git/factory/`; message content
   never enters its state or log.
4. Export `CLAUDE_WEEKLY_USED_PERCENT` and `CLAUDE_METER_AT` from a meter reading taken in the
   last ten minutes, then run
   `factory/tools/preflight.sh <result> <factory> <kickoff> <dispatch> <room-id>` from the
   factory repository. It refuses a
   missing, stale, or wrong-room observer. Then post the dispatch (`factory/dispatch/` in the factory
   repository, generated by `factory/tools/build_dispatch.py`) to the coordinator. That message is the
   only human input.
5. After the coordinator's final report and the full room export, stop the observer from the
   factory repository with `python3 factory/tools/room_meter.py stop --repo <result>`.

## Why it is built this way

- **Two builds of one spec.** The provided checks are only part of what is graded. So a seat from
  a different model family (the modeler) writes a small, slow, obviously correct executable model
  of the requirements without ever reading the product, and the gatekeeper runs the same random
  operations against both. The product is accepted only when they agree.
- **A third reader for shared blind spots.** The modeler and the gatekeeper share one model
  family, so they could misread a sentence the same way and agree. The auditor, on a third family,
  reads the requirements against the modeler's ledger and reports only misreadings that would
  change behaviour, each with a concrete input.
- **The reviewer cannot edit.** A reviewer that rewrites the code stops being a reviewer, so the
  gatekeeper may write checks but never product code, and every rejection carries a reproduction.
- **Evidence over claims.** Every rejection and acceptance names an exact revision; acceptance
  manifests record commands, exit codes and counts; the room shows every handoff.
- **Security as a checked requirement.** Passwords use a slow salted hash measured against the
  stated limits, identifiers are checked against the caller, pages send a strict content security
  policy, and every pinned dependency passes a vulnerability audit before acceptance.

Recovery rules the band follows without a human: resend a handoff that errors; read the repository
instead of waiting for a message about it; keep a handoff open until the receiver answers, and
restart a receiver that shows no activity for ten minutes; the coordinator names who holds the
next step before any turn ends.

## What the development runs taught the factory

Each rule below exists because a development run went wrong without it. A correction needed
twice became a mandate line.

| What went wrong | Rule it became |
|---|---|
| A handoff was lost and every seat waited | Delivery: resend on error, never wait on a fact the repository can answer |
| A receiver's runtime died and nobody noticed | Stalled seats, and a handoff stays open until the receiver answers |
| The spend rule told the sender to stop, which hid a dead receiver | A handoff that needs a reply is not finished until it gets one |
| The gatekeeper wrote its own probe of the next stage and rejected good work | Overshoot is decided by the provided check tool alone |
| A clean copy left a nested repository in a stage folder | Scratch work lives in the system temporary directory; the guard refuses gitlinks |
| 98% of tokens were context re-read on every step | Long command output goes to a file; seats read the summary and failing lines |
| The first auditor flagged wording as misreadings | Report only behaviour-changing misreadings, with a concrete input |
