# Browser verification plan

Run against an isolated candidate using synthetic users, at 375 and 1440 CSS pixels.
Gatekeeper owns execution/screenshots; this document is a plan, not passing evidence.

1. Visit `/`, `/requests`, `/split`, `/signup`, `/login`, `/authorizations` directly and by navigation. Check shared routes with HTML Accept versus JSON API. For every applicable page capture empty, filled, loading, refused and uncertain states; use fresh browser contexts for intro checks.
2. Map every UI selector row R2 in ledger to exact DOM assertions: unique matching node, required visible text, attributes, role/status-conditional presence, and no substitutes containing extra text inside exact-value elements. Test Unicode and empty notes.
3. Seed EUR/JPY/BHD, render exact amounts; submit decimal inputs with 0/2/3 places and reject excessive precision/nonnumeric without any network write. Confirm preview splits sum and equal server allocations, including zeros and reordered participants.
4. Payment identity: preserve form after success; repeat unchanged and compare key/body and one debit. Change each field to start a new identity. Lose a response after server commit; show uncertainty only, retry unchanged, compare exact original receipt and one debit. Restore successful state without stale errors.
5. Competing clients: spend funds remotely, submit stale form, assert refusal plus refreshed wallet/feed and retained inputs. Cancel a request remotely before stale pay; assert request-error and removal of obsolete action. Return two refresh groups in reverse order with different total/available/held/feed; latest must win in every displayed component.
6. Migration without reload: use the stage2 UI against compatible stage1-origin state; sign in, create pending request and retain uncertain payment form/key. Export stage1, import stage2 between browser requests, maintain browser context and form. Existing token, request payment and original payment retry must work.
7. Holds: seed all statuses and partial captures; wallet available is headline, held absent iff zero. New authorization, final partial capture, nonfinal partial capture via API followed by refresh, full capture, void and deadline expiry. Check original amount, cumulative amount conditional display, exact expiry text, role-specific controls and remaining capture prefill.
8. Keyboard and accessibility: visible labels, focus ring, logical tab traversal, no blocked controls, all text/control AA contrast, no horizontal scrolling. Repeat reduced-motion context with instantly correct state and no intro/parallax/burst.
9. Motion protection rules, each separately recorded: (1) ready elements visible/clickable, no scroll gating; (2) layers never intercept pointer; (3) no replaced navigation/smooth-scroll library; (4) animation properties only transform/opacity and writes/results never delayed; (5) required numeric text is immediately final; (6) no external runtime animation requests; (7) identical behavior across normal and automated clients; (8) no native dialogs, hidden-page loops or moving hovered controls.
10. Intro first session at most700ms, pointer-events:none, underlying page usable from first frame, layer removed at end; no repeated session intro. Hidden/offscreen ambient activity stops. Inspect accessible heading full string, exact single-node amounts/labels and decoration semantics. Compare all supplied font/art licensing and run-document attribution without copying reference materials.

Use network interception only to delay/drop responses, never to change financial response values. Record exact candidate revision, browser command, exit status and screenshot paths for every executed check. Credentials and exports stay in memory/private temporary artifacts; never publish them. No execution is claimed here.
